# 🏏 Cricbuzz LiveStats

A Streamlit dashboard that combines **live cricket data from the Cricbuzz API** with a **SQL database** of players, matches and performances. It includes 25 analytical SQL questions and a full CRUD module for player records.

> **Data note:** the sample data in the database (player names, scores, match results) is **synthetic**, generated by `scripts/seed_data.py` for SQL practice. It is not real cricket statistics. The *Live Matches* page and the *Official rankings* tab use **real data** from the Cricbuzz API. Venue names and countries are real; capacities are approximate.

## Features
| Page | What it does |
|---|---|
| **Home** | Project overview, database counts and status |
| **Live Matches** | Live and recent matches from the API, with full scorecards on demand |
| **Top Players** | Official rankings from the API, plus top run scorers and wicket takers from the database with charts |
| **SQL Analytics** | 25 SQL questions (beginner to advanced), results table, CSV download, chart, and a read-only custom SQL box |
| **CRUD Operations** | Create, read, update and delete players, and edit career stats, with validation and error handling |

## Tech stack
Python 3.12 · Streamlit · SQLite · pandas · Plotly · requests · python-dotenv · Cricbuzz Cricket API (RapidAPI)

## Project structure
```
main.py                     Home page / entry point
pages/                      Streamlit pages (Live Matches, Top Players, SQL Analytics, CRUD)
api/cricbuzz_client.py      API client with retries and clear error messages
services/player_service.py  CRUD business logic and validation
sql/schema.sql              Database schema (10 tables, indexes, 2 views)
sql/queries.py              The 25 SQL questions
utils/db_connection.py      Single place for database connections (adds STDDEV, read-only mode)
scripts/                    setup_database.py, seed_data.py, run_query.py, check_api.py
config.py                   Reads settings from .env
```

## Database design
10 normalised tables: `teams`, `players`, `venues`, `series`, `matches`, `innings`, `batting_performances`, `bowling_performances`, `partnerships`, `player_career_stats`. Primary and foreign keys, CHECK constraints, indexes, and the views `v_match_results` and `v_batting_detail`.

```
teams ──< matches >── venues        series ──< matches
matches ──< innings, batting_performances, bowling_performances, partnerships
players ──< batting_performances, bowling_performances, partnerships, player_career_stats
```

## Setup
1. **Create a virtual environment and install packages**
   ```
   python -m venv venv
   venv\Scripts\activate          (Windows)   |   source venv/bin/activate   (Mac/Linux)
   pip install -r requirements.txt
   ```
2. **Add your API key.** Create a RapidAPI account, subscribe to the *Cricbuzz Cricket* API, and create a file named `.env` in the project folder:
   ```
   RAPIDAPI_KEY=your_key_here
   RAPIDAPI_HOST=cricbuzz-cricket.p.rapidapi.com
   ```
3. **Create and fill the database**
   ```
   python scripts/setup_database.py --reset
   python scripts/seed_data.py
   ```
4. **Run the app**
   ```
   streamlit run main.py
   ```

Useful helpers: `python scripts/run_query.py all` runs all 25 queries and prints row counts; `python scripts/check_api.py` tests the API connection.

## Design notes
- **Security:** the API key lives only in `.env`, which is git-ignored.
- **Error handling:** the API client retries on timeouts, rate limits and server errors, and the pages show friendly messages instead of crashing. Custom SQL runs on a read-only connection and only allows a single `SELECT`.
- **API quota:** responses are cached (60 seconds for matches, longer for rankings and scorecards).
- **SQLite notes:** SQLite has no built-in standard deviation, so a `STDDEV` aggregate is registered in `utils/db_connection.py`. Stored procedures are replaced by views and saved queries.

## Known limitations
- Database statistics are synthetic (see the data note).
- Live data depends on the free API plan's quota and on which endpoints the provider currently offers.
